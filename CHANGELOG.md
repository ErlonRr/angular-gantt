# Changelog

All notable changes to **Gantry** (`@gantryjs/*`; the Angular package was published as `ngx-gantry` up to 1.0.1) are documented here.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/),
and this project adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

## [Unreleased]

### Added
- **Multi-framework packages**: `@gantryjs/core` (framework-free logic), `@gantryjs/vanilla` (`<gantry-element>` Web Component), and `@gantryjs/react`, `@gantryjs/vue`, `@gantryjs/svelte` bindings, each with a demo app under `apps/`.
- **Column sorting** (`@gantryjs/angular` and the Web Component): built-in columns are sortable; clicking a header cycles ascending → descending → original order.
- Release tooling with Changesets, CI workflow, and Web Component tests (happy-dom).

- **Configurable timeline**: N-tier header `scales` (`unit`, `step`, `format`, `className`), named `zoomLevels`, a new **Hour** view, `weekStart`, week label presets (`WEEK_FORMATS`: `W52`, `Week 52`, `4–11`, `4–11 Mar`), sticky upper-tier labels and `fitToWidth`.
- **Period delimiters**: `gridLines.major / minor / horizontal` (colour, width, dash) drawn through header and body — month boundaries now show in Week view too.
- **Non-working time**: `nonWorkingTime` (weekends, holidays, working hours per weekday, intensive hours; shade / hatch / disabled styles) and a `highlightTime` callback.
- **Element styling**: `bar` (height in px or % of the row, radius, progress, label position & template), `milestone` (size, diamond / circle / square), `groupBar` (summary or bar), `arrows` (width, head, rounded corners), per-task `progressColor` / `textColor` / `className`.
- **Task list panel**: `panel` (width in px or %, default 30%; min/max; resizable splitter; collapse toggle that restores the last width), horizontal scroll when columns overflow, a flexible fill column, resizable columns in every binding, `align` and `tableOnly` columns.
- **Views**: `view: 'split' | 'table' | 'chart'` with an animated table view and a toolbar switch; `options.toolbar` configures every toolbar part.
- **State**: `stateKey` (localStorage), `state-change` / `stateChange` event, `getState()` / `setState()`.
- Options playground in `apps/demo-vanilla`.
- **Demo site**: the Angular showcase is now the Gantry site — Home, Playground (every option, code in each framework's syntax, shareable `?setup=` links), Examples, Theming (presets and contrast check), Frameworks and an API reference generated from the Custom Elements Manifest — with its own look (amber accent of the today line, light and dark). The Web Component playground and the React, Vue and Svelte demos share it through the private `apps/demo-kit` package.
- **Split panel vs table view**: the panel next to the timeline is lean (`name`, `start`, `end`, `progress`) and the table view shows every useful field — type, a derived **status** (not started / in progress / overdue / done, with a coloured dot), duration, predecessors, and baseline start/end/variance when `baseline` is on. Choose them by key with `panel.columns` / `table.columns` (built-in keys need no `ColumnDef`), per view with `setColumnVisible(key, visible, view)`. Sorting reorders siblings at every tree level with a numeric collator; custom columns get `sortValue` and a `ColumnContext` (`render(row, ctx)`). New theme keys `statusNotStarted` · `statusInProgress` · `statusOverdue` · `statusDone`, new labels, `GanttTask.status`.
- **Demo data around today**: `createDemoData()` and `anchorToToday(template, { now, at })` in `@gantryjs/core/demo` move a plan by whole weeks so today sits inside it (about 40% in by default). Every demo (playground, React, Vue, Svelte, Angular showcase) now uses them, so the today marker is always inside the plan.
- **`initialScroll`**: `'auto'` (default) centres today only when it is near the tasks, otherwise shows the earliest task, so the first view is no longer empty for past or future projects; also `'today'`, `'start'`, a `Date` or `false`. `TimelineModel.extent` and the `initialScrollLeft()` / `zoomAnchorScroll()` helpers are exported from `@gantryjs/core`.

- **Shared interaction and state logic in `@gantryjs/core`** (both renderers use it instead of their own copies): virtual rows with pinned rows, horizontal windowing helpers, the selection reducer, view / panel-width resolution, versioned state persistence, tooltip and legend models, the keyboard map, grid navigation, keyboard move/resize sessions, accessible task names and screen-reader announcements — all translatable through `GanttLabels`.
- Date formats support `Do` (`'MMM Do'` → `Mar 1st`) and every `Intl` locale; new `dateNames()`, `isoWeek()`, `quarterOf()` helpers.

- **Keyboard model** (both renderers, the same rules from `@gantryjs/core`): one tab stop each for the toolbar, the task list and the bars. The task list is a row-first treegrid (`↑`/`↓`, `PgUp`/`PgDn`, `Home`/`End` between rows, the header row above the first; `→`/`←` expand or collapse a group, or move into the cells and back; `Enter` activates a row or sorts a column; `Space` / `Shift+Space` / `Ctrl+Space` select). The bars rove (`↑`/`↓` between rows, `←`/`→` pan one header cell) and `Enter` / `F2` start **keyboard move mode** (`←`/`→` move, `Shift` / `Alt` + `←`/`→` resize the end / start, `Enter` commits with the same `task-dragged` / `task-resized` events as a drop, `Esc` cancels). `F` fits the tasks to the screen, and `keyboard.characterShortcuts: false` turns off `+` `-` `T` `F` (WCAG 2.1.4). The focused bar gets a focus ring and its resize grips in one overlay (`g.gantt-bar-overlay`, from `BarVisual.focusRect` / `handles`), custom bars included; both panes get `scroll-padding-top`, so focus never hides under the sticky header.
- **Touch and pointer gestures**: a touch or pen press drags a bar after a 350 ms long-press (moving earlier pans the timeline, a tap toggles its tooltip), a mouse press after 3 px; dragging near the viewport's left or right edge auto-scrolls it (within 32 px, up to 18 px a frame); resize targets are `bar.handles.hitSize` wide (default 24 px, WCAG 2.5.8) with visible grips on the hovered, focused and (on touch screens) selected bars. Core: `hitTestBar`, `BarVisual.hitBox`, the gesture machine (`startGesture` … `endGesture`, `DRAG_THRESHOLD_PX`, `LONG_PRESS_MS`, `TOUCH_SLOP_PX`) and `autoScrollDelta`.
- **Zoom gestures and fit to screen**: Ctrl/⌘ + wheel, trackpad and two-finger pinches and Safari's gesture events zoom one level at a time around the pointer (`wheelZoom`, `pinchZoomSteps`, `anchoredScrollLeft`); `fitToScreen()`, the `F` key and the toolbar's new **Fit** button (`toolbar.fit`, default `true`) switch to the finest level that shows every task and scroll to the first one (`fitZoomLevel`, `fitScrollLeft`). Zoom changes are announced.
- **Chart states**: `loading` and `errorMessage` (Web Component properties and attributes `loading` / `error-message`, Angular inputs, React / Vue / Svelte props), the `retry` event (`RetryEvent`, `{ source: 'error' | 'dataSource' }`; Angular `(retry)`, wrappers `onRetry` / `@retry`) and empty-state content (`slot="empty"`, Angular `[ganttEmpty]`, React children, the Vue default slot, a Svelte `empty` snippet). The body shows a loading skeleton (`aria-busy`), an error box with Retry (`role="alert"`, `labels.errorTitle`) or the empty box (`labels.emptyState`); a failed first data-source page shows the error state too. Core `resolveChartState`, `skeletonRows`; Web Component part `state`.
- **Tooltip options**: `tooltip: { trigger: 'auto' | 'hover' | 'focus', showDelay, hideDelay, render }` (320 / 120 ms) and Angular's `<ng-template ganttTooltip>` (`GanttTooltipTemplateDirective`, `GanttTooltipTemplateContext`), which wins over `render`; `render(ctx)` returns a string or a DOM node. The tooltip opens on hover, on keyboard focus and on a tap. Core `placeTooltip` and the `reduceTooltip` machine.
- **Drag readout chip** (`.gantt-drag-readout`, "3 Mar – 6 Mar · 3 days", `labels.dragReadout`) next to a bar while it is dragged, resized or moved from the keyboard (`formatDragReadout`, `placeDragReadout`).
- **Marker lane** (`markers.lane: 'auto' | boolean`, default `'auto'`: shown when an annotation has a label): an 18 px lane under the header tiers with the annotation labels and a today chip, so labels no longer cover bars (`computeMarkerLane`); the table view has none.
- **Legend placement**: `legend.position: 'bottom' | 'toolbar'` (default `'bottom'`; `legendPlacement`).
- **Forced colors**: under `@media (forced-colors: active)` both renderers paint with system colours — `ButtonFace` / `ButtonText` bars, dashed critical bars (built-in bars get the class `gantt-bar--critical`), `Highlight` for the selection, today, the current period, the checked toolbar radio and every focus ring, `GrayText` lines and non-working time, `Canvas` / `CanvasText` tooltip, readout and state boxes.
- New theme key `focusRing` (`--gantt-focus-ring`, `#2563EB` light / `#60A5FA` dark) and labels `ariaBars`, `ariaTask`, `ariaMilestone`, `ariaGroup`, `ariaBarRole`, `ariaZoomLevels`, `ariaViews`, `fitToScreen`, `emptyState`, `errorTitle`, `dragReadout`. Core also exports the keyboard and a11y helpers both renderers use (`navigateTimeline`, `panScrollLeft`, `rovingIndex`, `tabStopIndex`, `keySelectionModifiers`, `createAnnouncer`, `barRoleDescription`, `GanttFlatRow.posInSet` / `setSize` / `parentIndex`) and the toolbar model (`buildToolbar`, `TOOLBAR_ICONS`).
- **Task styles**: `options.styles` (`task` / `group` / `milestone` by bar kind, `parent`, `levels[depth]`, `rule(row, ctx)`) and `GanttTask.style` (`color`, `progressColor`, `textColor`, `rowColor`, `className`, `height`, `radius`, `label`), resolved field by field in one cascade (`createStyleResolver`); custom bars read it in `ctx.style`. The flat `barColor` / `rowColor` / `textColor` / `progressColor` / `className` stay as deprecated aliases.
- **Rollup of parent rows**: `rollup` (`true` or `{ progress, dates, color, segments }`) gives each parent the progress, dates, status and colour of its children, with `segments` drawing a collapsed parent's children inside its bar, and `groupBar.collapsed` starts every parent collapsed.
- **Synchronised charts**: `createGanttSyncGroup({ zoom, scroll, range, panel })` and the `syncGroup` property / input / prop in every binding share the timeline range, zoom level, horizontal scroll and panel width between charts.
- **Density and responsive layout**: `density` (`'compact' | 'normal' | 'comfortable'`: rows, header tiers and toolbar controls), `responsive: { breakpoint, view }` (a narrow chart switches view, 640 px / `'chart'` by default, `false` turns it off), host `data-density` / `data-narrow` and the read-only `--gantt-row-height` / `--gantt-bar-height`.
- **Toolbar**: `toolbar.panelToggle` (a task-list button) and `toolbar.overflow: 'menu' | 'wrap'` (default `'menu'`: controls that don't fit move into a **More** menu, label `more`).
- **Week numbering**: `weekNumbering: 'iso' | 'us' | 'locale'`, `weekStart: 6` (Saturday), and core `weekOfYear()` / `weekYear()` / `ISO_WEEK` / `US_WEEK` / `localeWeekRule()`.
- **`arrows.routing: 'straight'`** (one line per dependency), **`formats.readoutFormat`** (drag readout dates), the theme key **`rowHoverBg`** (row hover in both panes) and the Vue **`#empty`** slot.
- **Examples gallery**: 20 cases, each in Angular, the Web Component, React, Vue and Svelte with the same controls, a code tab per framework and a "Known differences" section on the Frameworks page. The site deploy composes the four Vite demos under `/wc/`, `/react/`, `/vue/` and `/svelte/`.
- **Interactive editing** (`options.editing`, off by default; every binding): cells, the progress grip, drawn links and undo / redo, all through one change pipeline. Each change is a `GanttChange`, validated (links: no self link, duplicate, loop or parent ↔ child link; dates; progress; read-only tasks), offered to a cancelable `before-change` (`detail.preventDefault()`), applied, recorded and reported by `task-dragged` / `task-resized` / `task-progress-changed` / `dependency-created` / `dependency-deleted`, `task-updated`, `tasks-change` and `history-change` (Angular outputs `beforeChange`, `tasksChange`, …; wrapper callbacks `onBeforeChange`, `onTasksChange`, …). `editing.controlled` hands the tasks to the app (`tasks-change` with `applied: false`), `editing.validate` adds your own check, `task.editable: false` makes a row read-only (`draggable: false` still locks the dates only).
- **Cell editing**: F2, Enter, a double-click or typing opens the editor of the name, start, end, duration, progress and predecessors cells (`research FS+2d; scope SS`, `5d` / `2w` / `4h`) and of custom columns (`ColumnDef.editable`, `editor`, `editorOptions`, `exportValue`, `parse`, `validate`; `editor` can be your own DOM node, or an `<ng-template ganttCellEditor>` in Angular). Enter, Tab and Escape commit, move on and cancel; an invalid value keeps the editor open with `aria-invalid` and its message.
- **Links and progress with the pointer and keyboard**: a progress grip and a connector at each end of the hovered, focused or (touch) selected bar; drag a connector to another bar, click a connector then a bar, or press **L**, to link (the type follows the ends); click an arrow, then Delete, to remove it; ↑ / ↓ in move mode change the progress.
- **Undo and redo**: Ctrl/⌘+Z, Ctrl/⌘+Shift+Z or Ctrl+Y, the toolbar's Undo / Redo buttons (`toolbar.undo`) and `undo()`, `redo()`, `canUndo`, `canRedo`, `clearHistory()` (`editing.history`: 100 steps, edits of one task within 800 ms merge). New methods `addDependency()`, `removeDependency()`, `editCell()` and `focusTask()`; `GanttDataSource.patch()` / `PagedLoader.patch()` apply edits to a data source's items without refetching. Core exports the pieces: `GanttHistory`, `prepareChange`, `applyChange`, `invertChange`, `validateChange`, `editRules`, `resolveCellEditor`, `parsePredecessors`, `parseDuration`, `ProgressSession`, `LinkSession`.
- **Examples gallery**: five more cases in every framework (editing, cell editing, custom editors, dependency editing, controlled mode), 25 in all; the playground gets an Editing section.
- **README**: a new Configuration section "Editing" (options, pipeline and event order, controlled mode in all five frameworks, read-only rules, history, cells and the predecessors grammar, custom editors, links, methods) and the editing keys in Keyboard and focus, Touch and pointer, Screen readers and Forced colors.
- **README**: new Configuration sections for task styles, rollup, synchronised charts, responsive layout and density, week numbering, locales and format tokens (moved up from the Angular part), styling hooks, CSP, server-side rendering and the gallery.
- **Export and print** (every binding): `exportSvg()`, `exportCsv()`, `exportPng()`, `download('svg' | 'png' | 'csv')` and `print()` (async; Angular on the component, the others on the element: React `ref.current`, Vue the template ref's `element`, Svelte `bind:element`). Exports are drawn again from the chart's model in `@gantryjs/core`, not copied from the screen: every shown row (not only the mounted ones), the header, task list, bars, arrows, annotations and legend, colours resolved (`theme: 'current' | 'light' | 'dark'`), over the whole plan, the part on screen or a date `range`. The Web Component and Angular give byte-identical SVG and CSV. The SVG is portable (presentation attributes only, no `var(`, `<style>` or `foreignObject`, nothing loaded from elsewhere) and accessible (`role="img"`, `<title>`, `<desc>`, text as text); the PNG is drawn at `scale` 2 within the canvas limits (`RangeError` beyond); custom bars are exported as drawn (`renderBar` nodes, Angular bar components rendered off-screen; `customBars: 'builtin'`), keeping SVG drawing elements only — no script, style, animation, event handler, remote link or `url(…)` (the same rules headless: `sanitizeSvgMarkup`). An export draws the chart as it was when the method was called.
- **CSV export**: RFC 4180 text over the shown, all or chosen columns and every loaded task (or the shown rows), as data (local ISO dates, numbers, keys, predecessor ids) or as the cell texts, a column's `exportValue` first; keys that are raw task fields (`parentId`, `dependency`, `collapsed`…) export the field, so a CSV carries the tree; formula neutralisation against CSV injection (`=`, `+`, `-`, `@`, tab, CR get a leading `'` unless plain numbers) and a UTF-8 byte order mark in downloaded files.
- **Print**: `print()` paginates the whole plan in core (`paper`, `orientation` incl. `'auto'`, `margin`, `fit: 'width' | 'page' | 'none'`, rows never cut, header and task list repeated, the legend wrapped at the page width, "Title · Page n of N" footer, `maxPages` 200; a margin that leaves no room on the paper is a `RangeError`) and prints it through a hidden frame built with DOM APIs (strict CSP and Trusted Types; `img-src blob:` needed for PNG and print). `@media print` rules hide the toolbar, splitter and overlays when the page itself is printed.
- **Export events and toolbar menu**: `download()` and `print()` fire the cancelable `before-export` (`detail.preventDefault()`; Angular `(beforeExport)`, wrappers `onBeforeExport` / `@before-export`), then `export` with the file name and size or the page count (`(export)`, `onExport` / `@export`). `toolbar.export` (default off) adds an Export menu button (SVG image, PNG image, CSV table, Print…; `export.formats`) that moves into More first on a narrow toolbar; downloads and prints are announced, toolbar failures go to the alert region. New option `export` (`fileName`, `formats` and per-format defaults) and 11 labels. `<gantry-element>` fires `before-export` once its lazily loaded export code is in (Angular inside the call), and its export methods reject when that code can't be loaded.
- **Exports without a binding**: `createExportSource({ tasks, options })` with `exportChartSvg`, `exportChartCsv` and `exportChartPages` run in Node, workers and SSR; Angular's `exportSvg()` / `exportCsv()` also work during server rendering. New Angular type `GanttDownloadOptions`.
- **Examples gallery**: a new **Export and print** category with four cases in all five frameworks (Export SVG and PNG, Export a CSV table, Print on paper, Export from the toolbar), 29 in all; the playground gets an **Export** section (toolbar Export menu, PNG scale, paper, orientation, fit, CSV values and byte order mark) and its event logs list `before-export` and `export`.
- **README**: a new Configuration section "Export and print" (options, methods and events, what an export draws, custom bars, CSV values and formula neutralisation, pagination, Node and SSR, limitations), the export CSP note, and the Export menu in Toolbar, Screen readers and Forced colors.
- **Working calendar** (`options.calendar`, every binding; off by default): the weekends, holidays and working hours of `nonWorkingTime` also drive the arithmetic. With `calendar: true` durations count working days (`{ durations: 'working' | 'calendar', unit: 'day' | 'hour', skipNonWorking, hoursPerDay }`; `unit: 'hour'` uses `workingHours`, 09:00–17:00 when unset): the Duration and Variance columns, the tooltip, the drag readout, the duration and predecessor cells (`5d`, `1.5d`, `12h`, `2w`), the CSV `duration` / `variance` values, the rollup progress weights, and the critical path with its lags and float (`computeCriticalPath(tasks, resolveConfig(options))`; the tooltip shows the float, `labels.ttFloatHours` for hours). Drags, resizes, move mode and the start, end and duration cells keep a task's working length and snap starts forward and ends back off non-working time; a working move is one `task-dragged` and one undo step, and `editing.validate` gets `ctx.calendar`. Your own data is never snapped. `nonWorkingTime.style: 'none'` keeps the definition without painting the bands.
- **Working calendar in core**: `createWorkingCalendar()` / `WorkingCalendar` (O(log H) in the holidays), `formatDuration()`, `formatFloat()`, `taskDuration()`, `spanDuration()`, `measureBetween()`, `measureVariance()`, `addDuration()`, `snapTaskStart()`, `snapTaskEnd()`, `followTaskEnd()`, `editCalendar()`, `dateShiftDays()`, `dateReadingOf()` / `sameDateReading()`, `DEFAULT_WORKING_HOURS`, `DEFAULT_HOURS_PER_DAY`, and the labels `durationHours` and `ttFloatHours`.
- **Examples gallery**: three more cases in every framework (working days and holidays, a shift calendar in hours, the critical path in working time), 32 in all; the playground gets a Working calendar section and a `None` non-working style.
- **README**: a new Configuration section "Working calendar" (options, what counts working time, the editing rules, the Node helpers, limits), and the calendar notes in Editing and Export.

### Changed
- The framework-free packages are published under the **`@gantryjs`** npm scope (`@gantryjs/core`, `@gantryjs/vanilla`, `@gantryjs/react`, `@gantryjs/vue`, `@gantryjs/svelte`), and the Angular package, formerly `ngx-gantry`, is now **`@gantryjs/angular`**. The repository moved to [github.com/ErlonRr/gantryjs](https://github.com/ErlonRr/gantryjs) (old links redirect).
- `ViewMode`, `DependencyType` and `TaskType` are `as const` objects with a same-name union type instead of TypeScript enums: `ViewMode.Week` reads the same and plain strings such as `'Week'` are accepted. Optional properties of the public types accept `undefined` explicitly (friendly to `exactOptionalPropertyTypes`).
- `@gantryjs/angular`'s package declares `"type": "module"` (types were ambiguous for ESM resolvers).
- Task-list rows can be focused and selected with Enter / Space in both renderers.
- `@gantryjs/angular` now imports its types, timeline math, tree helpers and critical path from `@gantryjs/core` (no public API change).
- Angular and the Web Component render from the same `@gantryjs/core` model (`resolveConfig`, `buildTimeline`, `computeBarVisual`, `computeArrowVisual`, `DragSession`), so every option behaves identically. Custom bar components receive the computed geometry in `ctx.visual`.
- **Breaking (Angular)**: `(rowClick)` emits the clicked row (`GanttFlatRow`) from both panes, like every other binding, instead of its `RowGeometry` (`$event.row.task` becomes `$event.task`); `series` is a model (`[(series)]`; one-way `[series]` still works).
- **Breaking (core types)**: `TaskResizeEvent` has a required `edge: 'start' | 'end'` (`handle` is deprecated); `GanttLabels` has 24 new required labels and `ToolbarLabels` `undo` / `redo` (`options.labels` stays partial); `BarHit`, `BarVisual` (`progressGrip`, `connectors`), `ArrowVisual` (`points`, `selected`), `ToolbarItem` (`disabled`), `ResolvedToolbar` (`undo`) and `BarOverlayLink` (`sourceSide`) gained members, so objects built by hand need them.
- A rolled-up parent (`rollup.dates`) and an `editable: false` task no longer start a drag. In the Web Component, `updateTask()` / `appendTasks()` write the raw input (the data source's `patch()`), as Angular does, so the next page keeps them.
- Defaults: panel width `'30%'` (was 320px), bars `60%` of the row height, summary-style group bars, weekend shading in Day / Week views.
- **Angular 22** and **TypeScript 6.0**: `@gantryjs/angular` now requires `@angular/core` / `@angular/common` `^22.0.0` (Node `^22.12` or `>=24`). Dropped unused `@angular/animations`, `@angular/forms`, `zone.js` and the `dayjs` dependency of `@gantryjs/angular`. Tooling on Vite 8 (Rolldown), Vitest 5, `vite-plugin-dts` 5 with API Extractor, ESLint 10, Changesets 3; `@gantryjs/angular` gets its own unit tests (`ng test`, Vitest + happy-dom, zoneless TestBed); CI runs on Node 22 and 24.
- Development: ESLint (type-checked TypeScript, Angular templates with accessibility rules, Svelte, Vue, React hooks, and the core purity rules) and Prettier on the whole repository; one strict `tsconfig.base.json` for every package (`verbatimModuleSyntax`, `erasableSyntaxOnly`, and in the libraries `noUncheckedIndexedAccess` + `exactOptionalPropertyTypes`); `@gantryjs/core` compiles without DOM types; Angular builds with `strictTemplates`, `typeCheckHostBindings` and extended diagnostics as errors; pnpm catalogs for shared tool versions; Renovate; CI lint, format, time-zone tests and publint for `@gantryjs/angular`.
- Development: the repository uses one layout for every package — the Angular library moved from `projects/gantry` to `packages/angular` (published from `dist/gantryjs-angular`) and the Angular showcase from `projects/gantry-demo` to `apps/demo-angular`, which now owns the Angular runtime dependencies the workspace root used to declare.
- Development: Storybook removed (the showcase and the playground are the live demos); the Angular library and showcase build with `@angular/build` (no webpack left in the toolchain); browser QA is a Playwright suite (`pnpm e2e`, frozen clock, every binding) that also runs in CI.
- **Accessible default palette** (WCAG 2.2 AA): bars, arrows and selection `#2563EB`, critical `#DC2626`, today marker `#B45309`, darker muted text and baselines. The 1.x colours remain available as `LegacyLightTheme` / `LegacyDarkTheme`. Labels inside bars switch to a readable colour on custom `barColor`s (new `contrastRatio()` / `readableOn()` in `@gantryjs/core`).
- **Zero runtime dependencies**: `dayjs` is gone. Dates use a built-in `Intl` formatter with dayjs-compatible tokens; `locale` is any BCP 47 tag (no locale import), default `'en'` (the dayjs global locale is no longer read). A few CLDR abbreviations differ from dayjs's locale files (German `Mär`, Spanish `sept`).
- State saved with `stateKey` is versioned (`{"v":2,…}`), validated on load, and v1 snapshots are migrated.
- Bars' accessible names include the type, the dates (with times on hour scales) and the critical state; the tooltip and the legend come from shared core models (the legend can list critical path and baseline).
- Keyboard: `Ctrl/⌘+Shift+A` also selects all, shortcuts no longer fire with `Alt` / `AltGr`, and keys the chart doesn't handle keep their browser default; clearing an empty selection no longer emits `selectionChange`.
- Removed legacy helpers `PX_PER_DAY`, `HEADER_HEIGHTS`, `getTimelineRange`, `generateHeaderRows`, `generateGridLines`, `zoomIn`, `zoomOut`; `DragPreview` is `{ delta, unit }`; `GanttBarContext` fields are required; `criticalIds` is read-only.
- **Theming through CSS variables**: every colour of the render model is a `Paint` (a `var(--gantt-*)` token or an explicit colour) that both renderers apply as a CSS property; bar labels on theme fills use the new contrast tokens `--gantt-bar-text-on-{bar,milestone,critical}`; `resolveConfig(options, i18n, themeMetrics(theme))` takes only the theme metrics (no `cfg.theme`, no resolved colours), and `resolvePaint(paint, theme)` turns a paint into a concrete colour for custom renderers.
- **Web Component accessibility** (breaking for `@gantryjs/vanilla`): the host is no longer a tab stop and has no `data-theme` — it is a `region` named by `labels.ariaChart` through `ElementInternals` (host `role` / `aria-label` attributes where unsupported) with the custom states `:state(dark)`, `:state(dragging)` and `:state(loading)`; focus is delegated to internal tab stops (toolbar → one task-list row → splitter → timeline viewport, each with a focus ring), the splitter's `role="separator"` moved to `.gantry-splitter-handle` (with `aria-valuenow` / `aria-valuemin` / `aria-valuemax`, the panel width in px and its range) beside the collapse toggle, a polite `.gantt-sr-live` region announces selection-count and data-source load changes, and focus falls back to the timeline viewport when its control disappears. New labels `ariaToolbar` (also names the Angular toolbar) and `announceLoaded`.
- **One drag ghost for both renderers**: the dashed preview at 35 % opacity with a translatable movement label (`labels.dragDelta`, `+3d` / `-2h`) is computed by `@gantryjs/core` (`computeDragGhostVisual`); the Web Component adopts Angular's look. `isToday` annotations use the today colour in both renderers and in the legend.

## [1.0.0] — 2026-07-25

First public release.

### Added
- **`<gantry>` component** — root Gantt chart, standalone, `OnPush`, zoneless & signal-based (no RxJS, no `zone.js` required).
- **Task tree** with groups, milestones, collapse/expand, and per-row styling.
- **Dependencies** with all four types (`FS` / `FF` / `SS` / `SF`) and lag, plus a full **Critical Path** computation.
- **Baselines** for planned-vs-actual variance.
- **Drag & resize** of bars via Pointer Events (bar move + edge resize), with per-task `draggable` opt-out.
- **Selection** — single, Ctrl/Cmd-click toggle, Shift-click range, and keyboard (`Esc`, `Ctrl/Cmd+A`, `+/-`, `T`).
- **Tooltip** via the native Popover API (no CDK overlay).
- **Custom bars** through a pluggable `GanttBarRegistry` (`provideGanttBar`).
- **Custom left-panel columns** via the `columns` input or the declarative `<ng-template ganttColumn>` API (rich cell templates, resizable columns, resizable panel).
- **Lazy loading** with `createGanttDataSource` (`resource()` + `linkedSignal`) and an auto/manual "load more" trigger.
- **Timeline views** — Day / Week / Month / Quarter / Year with zoom.
- **Annotations** (vertical lines & shaded regions) and a **today marker**.
- **Legend** overlay (`showLegend`) describing the today line and annotations.
- **Theming** — light / dark / auto via CSS custom properties, live-patchable at runtime.
- **Internationalisation** — every UI string is overridable via `options.labels`
  (or `provideGanttLib({ labels })`), month/day names follow a dayjs `locale`, and
  dates/header labels accept custom `formats` (`dateFormat`, per-view `header`).
- Public math/data/CPM core is framework-free and unit-tested with Vitest.

### Fixed
- Header period labels no longer render as clipped "slivers" at the timeline edges
  in Month/Quarter/Year: sub-period padding is applied only in Day/Week views, so
  coarse views snap to whole periods.
- Virtual scroll no longer under-renders the last rows when the canvas height
  settles after the initial layout — a `ResizeObserver` recomputes the visible
  window, so dependency arrows always connect to real rows (no arrows drawn into
  empty space below the list).

### Dependencies
- Runtime: `dayjs` only. Peer: `@angular/core` & `@angular/common` `>=20.2.0`.
